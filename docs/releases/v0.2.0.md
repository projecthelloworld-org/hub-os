# HubOS v0.2.0 — Community-site monitoring

HubOS now brings reachability, device check-ins, approved field reports and support history into a working monitoring stack. Schools, community centres and libraries share the same canonical site model.

## Included

- Four Metabase dashboards: Community Operations, Availability & Connectivity, Devices & Field Evidence, and Collection & Support. They have site/country/date controls, read-only reporting and a generic telemetry view for additional plugins.
- Uptime Kuma 2.5.6 with persistent storage, automatic owned-instance setup, infrastructure checks, labelled demonstration targets and explicitly configured community checks.
- Read-only UniFi local Network, Headwind Community and ODK Central connectors; optional local Headwind/ODK deployments remain available.
- Trusted local connector packages without core import, query or schema edits for ordinary new metrics. A starter package and conformance tests are included; plugins are not sandboxed.
- Protected site/source/mapping administration, authenticated alert routing, deduplicated incidents, ownership, recovery and durable notification delivery.
- Separate demo/live installation modes, private service bindings, Caddy operator authentication, verified remote TLS and consistent backup/restore tooling.

The demonstration has five fictional Ugandan and five fictional Angolan sites, mixing schools, community centres and libraries. It is not evidence of a field deployment. Missing or stale evidence is unknown, uptime is reported with observation coverage, and infrastructure checks are not presented as community internet availability.

## Upgrading from v0.1.0

Take a consistent backup of databases, application storage, configuration and encryption secrets before upgrading. Keep the deployment's Docker project name and tool credentials unchanged. Rehearse restoration in isolated storage, and review locally edited release-owned files before allowing replacement.

The checksum-sealed installer stages the package before pausing services, preserves canonical identities, observations, mappings and tool accounts, and waits for migrations and required provisioning. Existing user-customized Metabase resources are preserved. Older unattributed status snapshots remain historical evidence, not current health; fresh collection must establish current status.

Do not turn a demonstration installation into a live deployment by reseeding or changing its mode. Use a separate directory and fresh storage. Keep the direct Metabase, Kuma, Headwind and ODK ports private; use a secure tunnel or their reviewed upstream HTTPS configuration.

The unchanged v0.1.0 package includes Metabase 0.60.7, which predates a critical security fix. See [Metabase compatibility and security guidance](../Metabase_Compatibility.md), [installation and upgrades](../Installation.md), and [backup and restore](../Backup_and_Restore.md). Replacing source files alone is not a database rollback.

## Compatibility and limits

UniFi is contract-tested against official local Network API shapes, including multiple controllers; no physical controller/hardware compatibility certification is claimed. There is no cloud Site Manager or undocumented legacy fallback. Headwind Community and ODK Central clients are also tested against isolated upstream applications. Confirm interface versions, read-only privileges, form mappings and certificate trust on each real deployment.

Release verification covers fresh/repeat installation, published-package upgrade, dashboard rendering and filtering, alerts and notification retries, privacy/access boundaries, worker recovery and isolated backup restoration. Device check-ins are not human usage, and operational telemetry does not establish educational or community impact.

This is a trusted single-installation model, not full multi-partner hosting or a security certification. Administrators remain responsible for patching, approved fields, incident response, retention and backup custody.
